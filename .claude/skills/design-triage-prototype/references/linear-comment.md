# Linear comment template

One comment per ticket. Post it only when the deployment URL has been checked and returned 200.

The first line is load bearing. The next run's de-dup gate looks for `**Design prototype for
review**` to decide whether this ticket has already been proposed. Do not reword it.

## Shape

One paragraph, then a numbered test list, then the links. Nothing else.

The paragraph covers five things in order and reads as prose, not as five labelled fragments: the
problem, the solution, why that shape and not another, why it is the confident call, and the
alternative if one was presented in the artifact. No em dashes. No bullet points inside it.

**Design prototype for review.** This is a proposal in the prototype app, not shipped behaviour.

## Worked example

```markdown
**Design prototype for review.** This is a proposal in the prototype app, not shipped behaviour.

A run that stopped told the end user "Un problème est survenu" and then proposed the same step
again, so nobody could tell which step broke or whether retrying was worth it. The prototype adds a
tenth widget state that names the step that stopped, states the cause, and offers a retry or a
person, and it draws the same failure in the builder's reasoning trace so support can see the break
without opening anything else. Naming the step beats a generic error banner because the useful unit
here is the step, not the run: three of the four steps worked, and a banner throws that away. I am
confident on the shape because the same trace object already renders on both surfaces, so this is
one change drawn twice rather than two designs that can drift. The alternative was a plain error
toast with a retry button, which is cheaper but leaves the support side exactly as blind as it is
now.

**How to test**

1. Open https://jimo-agent-xxxx.vercel.app/widget.html
2. Use the Preview state control at the top right and pick Execute · failed
3. Click the pill to open the run log
4. You should see the three steps that worked, the one that did not, the cause, and the two ways out

Deployment: https://jimo-agent-xxxx.vercel.app/widget.html
PR: https://github.com/fahmi-jimo-ai/jimo-agent/pull/4 (draft, branch `claude/upbeat-galileo-abc123-widget-legibility`)

---
_Generated by [Claude Code](https://claude.ai/code)_
```

## Rules

- Four or five test steps. If it takes more, the deep link is wrong, so link deeper.
- Step 1 is always the URL, including the path. Never make the reader find the page.
- The last step states what should be seen, so a failed test is obvious.
- Every ticket in an execution gets its own comment, written about that ticket, not a copy of the
  group summary with the id swapped.
- No comment at all if the deployment did not return 200.
